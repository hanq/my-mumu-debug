# 功能缺口与交互布局评估（2026-11-07）

> 评估对象：当前工作区代码（基线 `760ab8f`，含本次新增的「清空请求/清空日志/暂停抓包/右键复制」）。
> 评估方法：逐条对照 `spec.md` F1–F5 与实际接线情况，核对 `app.go` 绑定、`internal/` 实现与 `frontend/src/App.vue` 的 UI 使用，不凭印象判断。
> 结论：主链路（检测→连接→Root→装证书→抓包→查看）已闭环；**5 项基础缺口、6 项高频便利项、7 项打磨项** 待补，另有 3 处布局会随功能增加明显变挤。

## 1. 已有能力（基线）

- 环境检测（MuMu 安装/实例/自带 adb）、adb 连接/断开、root 校验、ADB Shell 外挂窗口
- 证书幂等安装（zygote 命名空间）、目标 APP 重启、进程 TCP 连接诊断
- 一键开/停抓包、暂停/恢复记录（标记文件 + addon 轮询）、代理设置与清理
- 请求列表（时间/方法/URL/状态/耗时）、详情（响应体/HEX/请求体/请求头/响应头）
- 媒体预览、响应体另存、复制为 cURL/PowerShell、URL/头/体右键复制
- 清空请求列表（含响应体临时文件）与清空运行日志
- TLS 握手失败事件、mitmdump 异常退出事件

## 2. P0 基础缺口（影响可用性或数据安全）

| # | 功能 | 现状证据 | 影响 | 布局建议 |
|---|---|---|---|---|
| 1 | 会话落盘 | `internal/capture.Options` 有 `FlowPath`/`LogPath`，但 `app.go` 的 `StartCapture` 从不赋值；`configDir()` 为死代码 | `spec.md` F5 承诺的 `flows.mitm`（可 `mitmweb -r` 回放）与 mitmdump 日志均未落地，问题无法离线复现 | 04 步骤加「保存会话」开关；日志路径写进运行日志首行，不新增面板 |
| 2 | 代理残留恢复 | `StopCapture` 按钮 `:disabled="!capturing"`；启动时未调用已实现的 `adb.GetGlobalProxy` | 崩溃/强杀后 APP 一直指向 `10.0.2.2:8888`，UI 内无法解除，只能重开抓包再停 | 04 步骤常驻「恢复 APP 直连」次级按钮；状态栏显示当前全局代理 |
| 3 | 全量 body 查看 | addon `MAX_BODY=8000` 截断文本，详情只展示截断文本；完整响应体仅在 `resp_body_file`（只能另存/HEX）；请求体完全不落盘 | 大 JSON/长文本无法在应用内阅读；请求体无法回溯 | 响应体页加「已截断 → 查看完整内容」入口（后端分页读文件）；请求体同步落盘 |
| 4 | 过滤完整性 | 仅有 URL 关键字 + 写死的 `/tongji\|dcloud.net/` 噪声规则 | `spec.md` F5 要求的方法/状态码过滤缺失；排查 4xx/5xx 只能肉眼翻 | 工具行放 URL + 方法 + 状态三个紧凑控件；噪声名单可编辑 |
| 5 | 环境状态可见性 | `DetectEnvironment` 只返回 MuMu 信息；`CAExists` 绑定前端从未调用；`ListThirdPartyPackages` 绑定从未调用 | 无法确认 mitmdump/CA 是否就绪；前台探测失败时只能手打输入包名 | 01 步骤加 adb/mitmdump/CA 状态摘要；03 步骤加「从已安装应用选择」下拉 |
| 6 | 抓包中操作保护 | 断开 ADB 仅判断 `!serial`；实例下拉抓包中仍可切换，会覆盖 `a.serial` | 停止时会清错实例的代理，产生"幽灵代理" | 抓包中禁用实例切换与断开（或二次确认），不改布局 |
| 7 | 端口可配置 | 前端固定传 `8888`，底部 `PORT: 8888` 为字面量 | `spec.md` 风险表要求的可配置端口与占用诊断未实现 | 端口输入框放 04 步骤，底部显示实际值 |

## 4. P2 打磨项

- 2000 行后 `flows.value.shift()` 静默丢弃最老记录（spec 的虚拟滚动未做），建议显式提示「已丢弃 N 条」。
- 详情面板固定 `height: 260px` 不可拖拽，长正文阅读空间不足。
- `main.go` 未设 `MinWidth/MinHeight`，窗口缩小后表格与详情会被压扁（建议 1024×640）。
- 步骤没有完成态标记，状态仅靠按钮 disabled 隐式表达；建议步骤头加 `ADB/ROOT/CERT/LIVE` 徽标。
- 抓包状态在暂停按钮、tab-status、底部状态栏重复三处，建议收敛为「底部状态 + 按钮态」，tab-status 改为请求计数/速率。
- 空态、TLS 失败、私有协议边界仅一行文案，建议改为带下一步操作的提示块。
- 无独立「重启目标 APP」按钮（现只能借开抓包/装证书顺带重启）。

## 5. 布局评估

| 区域 | 评价 | 问题与建议 |
|---|---|---|
| 标题栏 40px | 合理 | 可加运行态圆点，与状态栏呼应 |
| 左列步骤 330px | 顺序合理、偏挤 | 04 区已含 开启/停止/暂停/装证书/说明 五项；装证书收进「高级」，端口与会话落盘放此，路径信息上移 01 |
| 右列 TAB 栏 | 合理 | 状态重复，见 P2 |
| 请求工具栏 | 扩展性差 | 现「URL + 噪声 + 清空」刚好；建议固定为 URL(自适应) + 方法 + 状态 + 筛选 + 清空 |
| 请求表 | 合理 | 缺大小列；URL 截断无 tooltip；WS 行展示不完整 |
| 详情区 | 固定高度、6 tab 临界 | 加可拖拽分隔条（160px–60%）；动作按钮图标化；新增概览 tab |
| 右键菜单 | 合理 | 建议分组并补「复制请求体/在浏览器打开/另存响应体」 |
| 运行日志 | 功能不足 | 清空位置正确；缺自动滚动/过滤/级别区分 |
| 状态栏 | 信息失真 | 显示真实端口、代理地址、CA 状态、暂停态 |
| 窗口尺寸 | 缺下限 | `main.go` 补 `MinWidth/MinHeight` |

## 6. 建议落地顺序

1. 代理残留恢复 + 抓包中禁用断开/切换实例（安全兜底，改动小）
2. 环境状态摘要 + 应用列表选择 + 端口可配（接线已实现但未使用的绑定）
3. 会话落盘（flows.mitm/日志）+ 方法/状态过滤（补齐 spec F5）
4. 全量 body 查看 + 详情「概览」页（日常最大痛点）
5. 日志面板增强、快捷键、配置持久化
